# DLMM Sentinel

Русскоязычное desktop-приложение для исследования токенов и сравнения эффективности пулов. Текущая версия — **0.3.31**. Основная платформа — Windows 10/11 x64.

## Возможности

- Карточка токена по адресу и выбранной сети: Solana, BSC, Ethereum, Base и Robinhood Chain.
- Числовые показатели GMGN: капитализация, холдеры, концентрация, бандлеры, phishing, наблюдатели, Total Fees и объёмы за 5 минут и час. Подсветка значений и правила Runner / Slowcook.
- Анализ X/Twitter через Grok: нарратив, значимые аккаунты, красные и зелёные флаги, оценка 0–100 и ссылки. GetMoni читается отдельно, если доступен.
- Meteora для Solana и GeckoTerminal для остальных сетей: поиск пулов, до 10 лучших с TVL > $1 000, сортировка по Fee/TVL за 5 минут или час.
- Для Meteora DLMM учитываются базовая и динамическая комиссии, Active TVL и Bin.
- Суточный Fee/TVL показывается как линейный пересчёт текущего окна: 5 минут × 288 либо час × 24. Суточные значения округляются до одного знака.
- Независимые кнопки обновления числового анализа, Grok и пулов. Архив карточек с удалением.
- Demo mode с явно обозначенными демо-данными, mock-провайдеры и тестовые сценарии.

Приложение не торгует, не подписывает транзакции и не запрашивает seed phrase или приватный ключ. Fee/TVL — оценка эффективности пула при текущей ставке комиссии, а не фактически полученная доходность позиции. Суточный пересчёт предполагает сохранение темпа.

## Установка готового приложения

1. Откройте [последний релиз](https://github.com/metrdubay-alt/dlmm-sentinel/releases/latest).
2. В разделе **Assets** скачайте `DLMM.Sentinel.Setup.0.3.31.exe`. Архивы **Source code** — исходники для разработки, а не установщик.
3. Запустите установщик, выберите папку и завершите установку. Ярлык **DLMM Sentinel** появится на рабочем столе и в меню «Пуск».
4. Запустите приложение. Node.js, npm и Git для готового приложения не нужны. Для получения реальных данных нужен интернет.

Установщик не имеет цифровой подписи издателя, поэтому Windows может показать предупреждение. Скачивайте файл именно из этого репозитория. Для проверки скачанного файла сравните результат с `SHA256SUMS.txt` в том же релизе:

```powershell
Get-FileHash -LiteralPath '.\DLMM.Sentinel.Setup.0.3.31.exe' -Algorithm SHA256
```

Чтобы обновиться, закройте приложение и установите новую версию поверх прежней. Сохранённые карточки и входы находятся отдельно в профиле приложения. Перед важным обновлением можно сделать копию `%APPDATA%\DLMM Sentinel` при закрытом приложении. Эта копия содержит личные данные и сессии; не отправляйте её другим людям.

## Как пользоваться

### Первый запуск и входы

1. В верхней части окна переключите **ДЕМО-ДАННЫЕ** на **Реальные источники**. Демо предназначено для знакомства с интерфейсом, его цифры не описывают реальный токен.
2. В блоке **Входы в источники** нажмите **GMGN**, войдите в свой аккаунт и дождитесь загрузки сайта.
3. Нажмите **X**, войдите в свой аккаунт. Grok использует ту же сессию X; при необходимости откройте **Grok** и проверьте, что он доступен вашему аккаунту.
4. При желании войдите в **GetMoni**. Если дневной лимит закончился, отключите «Использовать GetMoni при обновлении» в карточке и продолжайте без него.
5. Зелёная кнопка источника означает, что приложение распознало активный вход. Серая означает, что вход не подтверждён; подпись рядом уточняет причину. Предупреждение о лимите отдельно от статуса входа.

У каждого пользователя свои аккаунты, лимиты и данные. Входы сохраняются между запусками, но сайт может завершить сессию и потребовать повторную авторизацию. Вход в обычном браузере или Codex не равен входу во встроенном окне приложения. Для публичных данных пулов отдельно входить в Meteora или CoinGecko не требуется.

### Новый токен

1. Нажмите **Новый токен**.
2. Выберите сеть и вставьте полный адрес контракта. Особенно важно правильно выбрать сеть для адресов `0x…`: один формат используется в нескольких сетях.
3. Нажмите **Запустить анализ**.
4. Дождитесь завершения этапов. Тикер и профиль X заполняются по найденным данным; если источник недоступен, часть результата может остаться пустой.

Карточка состоит из трёх разделов:

| Раздел | Что смотреть | Как обновить отдельно |
| --- | --- | --- |
| Числовой анализ | GMGN, объёмы, холдеры, риски концентрации и рекомендуемый режим Runner / Slowcook | «Обновить числовой анализ» |
| Оценка Twitter | Ответ Grok, нарратив, балл, флаги, аккаунты и ссылки | «Обновить анализ Grok» или «Анализировать Twitter» |
| Объёмы и эффективность пулов | До 10 пулов с TVL > $1 000; комиссия, Bin, объёмы и Fee/TVL | «Обновить пулы» |

Нажатие кнопки числового анализа обновляет только GMGN. Grok и пулы обновляются своими кнопками. Пока запрос выполняется, соответствующая кнопка заблокирована. Автоматические рабочие окна источников скрыты; кнопка входа открывает окно для ваших действий.

### Как читать пулы

- **Fee/TVL 5м** и **Fee/TVL 1ч** — оценка комиссионной эффективности за выбранный интервал. Чем показатель выше, тем выше пул при сортировке по этому интервалу.
- Для **Meteora DLMM**: объём × (базовая комиссия + динамическая комиссия на момент снимка) / Active TVL. Bin указан рядом с комиссией в «Пул / DEX».
- Для остальных рассчитываемых пулов: объём × комиссия / общий TVL.
- **Δ объёмов торгов** — изменение среднего объёма в минуту за последние 5 минут относительно предыдущих 25 минут: `(V5 / 5) / ((V30 − V5) / 25) − 1`, в процентах. +100% означает удвоение темпа, −50% — снижение вдвое. Значение округлено до целых. Если в предыдущем периоде объём нулевой или данных нет, показано «—».
- **24ч** под пятиминутным значением — умножение на 288, под часовым — на 24. Это пересчёт при сохранении темпа, без сложного процента; не фактически заработанные за сутки комиссии.
- Суточный показатель отображается с одним знаком после запятой. Расчёты и сортировка используют полную точность.
- Более насыщенный зелёный цвет показывает большую эффективность относительно остальных пулов в таблице. Он не означает низкий риск токена.
- «—» означает отсутствие данных для расчёта, а не нулевую комиссию или доходность. Для некоторых DAMM v2 пулов расчёт пока недоступен.

### Архив

Раздел **Архив** хранит ранее созданные карточки с тикером, адресом и датой проверки. «Открыть карточку» показывает сохранённый результат. Старые данные сами по себе не становятся актуальными: смотрите время снимка и обновляйте нужный раздел. «Удалить» удаляет выбранную карточку после подтверждения.

## Если что то не работает

| Ситуация | Что проверить |
| --- | --- |
| Кнопки обновления неактивны | Включены ли реальные источники; не выполняется ли другой этап анализа |
| После входа источник остаётся серым | Откройте источник именно кнопкой приложения, завершите вход и дождитесь загрузки; прочитайте подпись состояния |
| Grok недоступен | Доступен ли он в вашем аккаунте X, не закончился ли лимит; при необходимости войдите повторно |
| GetMoni не вернул счёт | Лимит и правильность профиля; счёт связанного автора не является счётом официального аккаунта токена |
| Не получены числовые данные | Правильность сети и адреса, вход GMGN и загрузка страницы; повторите отдельное обновление |
| Пулы загружаются долго | Дождитесь запроса: публичные API ограничивают частоту. При ошибке повторите позже, не запускайте несколько обновлений подряд |
| Данных нет у части пулов | Нет опубликованной ставки комиссии, истории или другой обязательной величины; приложение не подставляет её из соседнего пула |
| Prisma сообщает EPERM при сборке | Закройте приложение и тестовые Electron-процессы, затем повторите генерацию |

При сообщении об ошибке укажите версию, сеть, публичный адрес токена, шаги и текст ошибки. Не прикладывайте папку профиля приложения, cookies, пароли, коды входа или API-ключи.


## Запуск разработки

Нужны Windows x64, Node.js 22.12+ или 24 LTS и npm. Интернет требуется для установки зависимостей и работы реальных источников.

```powershell
git clone https://github.com/metrdubay-alt/dlmm-sentinel.git
cd dlmm-sentinel
npm ci
Copy-Item .env.example .env
npm run prisma:generate
npm run dev
```

Клиент Prisma генерируется локально. Иконки уже включены в репозиторий; пересоздать их можно командой `npm run icons:generate`.

По умолчанию включён демо-режим. Для реальных данных выберите «Реальные источники» и войдите в нужные сервисы через кнопки приложения. Вход в X используется и для Grok. Сессии браузера Codex или обычного браузера не переносятся автоматически в Electron.

Доступность Grok и GetMoni зависит от аккаунта и лимитов сервиса. GMGN, X и GetMoni читаются через встроенные окна; изменения интерфейсов сайтов могут потребовать обновления адаптеров. Публичные данные Meteora и GeckoTerminal не требуют входа; источники могут ограничивать частоту запросов. Недоступные значения не заменяются демо-данными.

## Проверка и сборка

```powershell
npm run typecheck
npm run lint
npm test
npm run build
npx tsx scripts/verify-build.ts
npm run test:e2e
```

Запускайте E2E после сборки. Тесты используют отдельные временные каталоги данных. Для сборки Windows-установщика:

```powershell
npm run dist:win
```

Результат появляется в `release/`. NSIS создаёт ярлыки на рабочем столе и в меню «Пуск». Установщик не подписан сертификатом издателя. Сборки macOS/Linux предусмотрены конфигурацией, но не проверены.

Если генерация Prisma сообщает, что файл занят, закройте запущенный экземпляр приложения или тестовый Electron и повторите команду.

## Структура

| Каталог | Содержание |
| --- | --- |
| `src/main` | Electron, чтение источников, хранение и IPC |
| `src/renderer` | React UI на русском языке |
| `src/shared/analysis` | Схемы данных, правила оценки, расчёты и промпт Grok |
| `src/tests` | Unit, integration и Electron E2E тесты |
| `prisma` | Схема SQLite и миграции |
| `scripts` | Разработка, сборка, демо-база и проверка артефактов |
| `assets`, `build` | Исходник иконки и готовые ресурсы приложения |

Точный промпт Grok находится в `src/shared/analysis/grok.ts`, функция `buildGrokPrompt`. Формула Meteora DLMM в `src/main/services/meteora-pools.ts`: объём × (базовая Fee + Dynamic Fee) / Active TVL. Формула остальных пулов использует общий TVL. Ставки в этих формулах заданы в процентах, поэтому результат также выражен в процентах.

## Локальные данные

SQLite, сессии сервисов и зашифрованные credentials хранятся в профиле приложения, обычно `%APPDATA%\DLMM Sentinel`. Они не входят в репозиторий. Также исключены локальные исследования, выгрузки аккаунтов, Word-документы, установщики и временные диагностические скрипты.

В тестовых данных есть сохранённый публичный ответ GeckoTerminal для проверки обработки минутных свечей. Он используется только как регрессионный пример, не как актуальный рыночный снимок.

## Совместная доработка

Для товарища подготовлена ветка [`contributor`](https://github.com/metrdubay-alt/dlmm-sentinel/tree/contributor). Основная ветка — `main`. Изменения из рабочей ветки отправляются в `main` через **Pull Request** и проверку владельцем.

### С доступом участника репозитория

Владелец приглашает участника по его GitHub-логину. После принятия приглашения:

```powershell
git clone --branch contributor https://github.com/metrdubay-alt/dlmm-sentinel.git
cd dlmm-sentinel
npm ci
Copy-Item .env.example .env
npm run prisma:generate
```

Для разработки используйте отдельный каталог данных, чтобы экспериментальная версия не меняла архив установленного приложения:

```powershell
$env:SENTINEL_DATA_DIR = Join-Path $PWD '.local\contributor-data'
npm run dev
```

В этой отдельной среде потребуется войти в сервисы заново. Для сборок и тестов следуйте разделу «Проверка и сборка» выше.

Перед началом следующей задачи синхронизируйте ветку, предварительно сохранив свои изменения:

```powershell
git switch contributor
git pull --ff-only origin contributor
git fetch origin
git merge origin/main
```

После изменений и успешных проверок:

```powershell
git status
git add src README.md
git diff --cached
git commit -m "Describe the change"
git push origin contributor
```

В `git add` перечисляйте именно изменённые файлы: приведённая команда — пример. Затем откройте [создание Pull Request из contributor в main](https://github.com/metrdubay-alt/dlmm-sentinel/compare/main...contributor?expand=1), опишите изменение и выполненные проверки. Владелец проверяет и объединяет результат. Не используйте force push. Передавайте самостоятельные изменения небольшими Pull Request.

### Без приглашения

Публичный код можно дорабатывать и через **Fork**: создайте свою копию кнопкой Fork на GitHub, клонируйте её, создайте рабочую ветку, отправьте изменения в свой fork и откройте Pull Request в `metrdubay-alt/dlmm-sentinel:main`. Этот вариант не требует права записи в исходный репозиторий.

### Правила изменений

- Проверяйте типы, lint, тесты и production build перед Pull Request. E2E запускаются после сборки.
- Сохраняйте русский интерфейс, маркировку демо-данных и явное отображение отсутствующих данных.
- Изменения порогов, формул и промпта Grok описывайте в Pull Request; добавляйте регрессионные проверки для ошибок расчёта.
- Не добавляйте `.env`, ключи, базы, сессии браузеров и пользовательские отчёты в Git. `.gitignore` уже исключает рабочие данные и сборки.
- Ветка `main` предназначена для проверенных изменений. Участники работают в отдельных ветках и создают Pull Request.
